# Catch Typing / 캐치 타이핑

> 실시간 단어 쟁탈을 중심으로 여러 아케이드 규칙을 즐기는 2D 픽셀 아트 멀티플레이 타이핑 게임

| 항목 | 내용 |
|---|---|
| 문서 종류 | 게임 기획서 초안 (GDD) |
| 버전 | v0.1 |
| 작성일 | 2026-08-27 |
| 장르 | 실시간 멀티플레이 타이핑 아케이드 / 파티 / 경쟁·협동 |
| 핵심 플랫폼 | PC 웹 또는 PC 클라이언트 우선, 추후 확장 검토 |
| 권장 플레이 인원 | 2~8명 (모드별 상이) |
| 한 판 길이 | 약 30초~3분, 레이드 3~5분 |
| 핵심 키워드 | 선착순, 정확도, 쟁탈, 콤보, 자동 방해, 오락실, 픽셀 아트 |

---

## 1. 프로젝트 소개

**Catch Typing / 캐치 타이핑**은 화면에 동시에 나타나는 여러 단어와 짧은 문장을 플레이어들이 실시간으로 골라 입력하고, 가장 먼저 정확하게 전송해 목표물을 획득하는 타이핑 아케이드 게임이다.

타자 속도만 겨루는 전통적인 타자 연습 게임에서 벗어나, 어떤 목표를 노릴지 판단하는 시선 처리, 상대와 목표가 겹쳤을 때의 긴장, 콤보를 유지하는 정확도, 상황에 따른 위험·보상 선택을 결합한다. 하나의 공통 타이핑 엔진을 단어 쟁탈전, 접시 사격, 레이싱, 디펜스, 협동 레이드 등 서로 다른 오락기에 적용하여 짧고 반복 가능한 미니게임 컬렉션으로 확장한다.

### 1.1 한 문장 소개

> 보이는 단어를 골라 누구보다 먼저 정확히 전송하고, 콤보로 상대의 화면을 흔드는 실시간 타이핑 오락실.

### 1.2 프로젝트 목표

- 초보자는 보이는 단어를 입력하는 것만으로 즉시 참여할 수 있다.
- 숙련자는 속도, 정확도, 목표 선택, 페이크와 견제를 통해 실력 차이를 만든다.
- 30초 안에도 긴장과 역전이 발생하는 짧은 아케이드 경험을 제공한다.
- 동일한 입력 체계를 재사용하면서도 모드별 승리 조건과 전략을 분명히 다르게 만든다.
- 플레이 자체가 타자 실력 향상으로 이어지되, 학습 도구보다 게임으로 먼저 인식되게 한다.

### 1.3 명칭 메모 및 법적 검토

“캐치 타이핑”이라는 이름은 **‘캐치! 티니핑’에서 착안한 언어유희**이자, 단어를 먼저 입력해 “낚아챈다(catch)”는 게임 핵심을 함께 표현한다.

다만 기존 작품명과의 발음·인상 유사성, 지정상품 및 서비스 분류, 국가별 상표 등록 여부, 검색 노출 혼동 가능성을 출시 전에 반드시 검토해야 한다. 본 명칭은 개발용 가칭으로 취급하며, 상용화 전 상표 검색과 법률 자문을 거쳐 유지·변경 여부를 결정한다. 로고, 캐릭터, 색상, 홍보 문구는 기존 IP를 연상시키는 표현을 의도적으로 피한다.

## 2. 핵심 콘셉트

### 2.1 디자인 기둥

1. **보고, 고르고, 정확히 친다**
   단순한 입력 속도뿐 아니라 여러 목표 중 하나를 선택하는 판단이 중요하다.

2. **서버가 결정하는 실시간 쟁탈**
   같은 목표를 노린 순간, 서버에 먼저 도착한 유효 입력만 성공한다.

3. **잘할수록 압박이 커지는 콤보**
   연속 성공은 점수뿐 아니라 상대에게 짧은 자동 방해를 보내 경기의 흐름을 만든다.

4. **타이핑 엔진 하나, 오락기 여러 대**
   입력 감각은 일관되게 유지하면서 각 미니게임의 목표, 공간, 우선순위, 협력 방식은 다르게 설계한다.

5. **짧고 강한 오락실 손맛**
   입력 성공 순간의 소리, 흔들림, 파편, 점수 팝업을 통해 키보드 조작을 물리적인 타격처럼 느끼게 한다.

### 2.2 목표 감정

- “저 단어는 내가 먼저 봤다.”
- “동시에 노렸는데 내가 간발의 차로 가져왔다.”
- “콤보를 한 번만 더 이어 방해를 발동하고 싶다.”
- “방해를 버티고 역전했다.”
- “다른 오락기도 한 판 해보고 싶다.”

### 2.3 비목표

- 긴 문서를 그대로 베껴 쓰는 타자 연습 프로그램
- 장비 능력치가 승패를 좌우하는 성장형 RPG
- 강한 화면 방해로 입력 자체를 장시간 불가능하게 만드는 게임
- 모드의 외형만 다르고 승리 조건은 모두 같은 미니게임 모음

## 3. 코어 게임 루프

### 3.1 한 판의 흐름

1. 플레이어가 오락실 로비에서 게임기를 선택한다.
2. 공개 방, 빠른 대전 또는 친구 방으로 매칭한다.
3. 3초 카운트다운 후 모든 플레이어에게 동일한 목표 상태가 동기화된다.
4. 플레이어는 화면의 3~5개 단어 또는 짧은 문장 중 하나를 선택해 입력한다.
5. 입력을 전송하면 서버가 정확성, 목표 유효성, 도착 순서를 판정한다.
6. 성공 시 목표 획득, 점수, 콤보, 시청각 피드백이 발생한다.
7. 획득된 목표는 사라지고 새 목표가 즉시 또는 짧은 연출 후 보충된다.
8. 콤보 임계치에 도달하면 상대에게 자동 방해가 발동한다.
9. 제한 시간 또는 모드별 종료 조건이 충족되면 결과를 정산한다.
10. 재대전, 다음 오락기, 로비 복귀 중 하나를 선택한다.

### 3.2 세션 루프

플레이 → 결과 및 개인 지표 확인 → 랭크/시즌 진행도 획득 → 스킨 또는 꾸미기 해금 → 같은 모드 재도전 또는 다른 오락기 선택.

## 4. 기본 쟁탈 규칙

### 4.1 목표 생성

- 한 화면에 **3~5개의 단어 또는 짧은 문장**이 동시에 등장한다.
- 모든 플레이어는 원칙적으로 같은 목표 ID와 문자열을 본다.
- 누군가 목표를 획득하면 해당 목표는 즉시 비활성화되고 새 목표로 보충된다.
- 기본 모드는 30~90초 동안 목표 풀이 끊기지 않도록 유지한다.
- 목표마다 길이, 난도, 희귀도에 따른 기본 점수를 부여할 수 있다.

### 4.2 입력과 전송

- 플레이어는 별도 목표 클릭 없이 입력을 시작할 수 있다.
- 현재 입력값과 접두사가 일치하는 목표를 후보로 강조한다.
- 여러 목표가 같은 접두사를 공유하면 입력이 분기될 때까지 모두 후보로 유지한다.
- `Enter` 또는 설정된 전송 키를 눌러 입력을 제출한다.
- IME 조합 중인 한글은 조합 완료 전 제출·오타 판정하지 않는다.
- 대소문자, 문장부호, 띄어쓰기 허용 범위는 플레이리스트 규칙으로 명시한다.

### 4.3 획득 판정

유효한 목표에 대해 **서버가 먼저 수신하고 검증한 정확한 제출**이 승리한다.

- 성공: 제출 문자열이 활성 목표 문자열과 정확히 일치하며 최초 유효 제출인 경우.
- 쟁탈 패배: 같은 목표를 정확히 제출했지만 서버에서 이미 다른 플레이어가 획득한 경우.
- 오타: 활성 목표와 일치하지 않는 문자열을 제출한 경우.
- 만료: 제출 처리 전에 목표가 시간 만료 또는 게임 규칙에 따라 제거된 경우.

클라이언트 화면의 연출은 예측적으로 먼저 보여줄 수 있으나, 점수·콤보·소유권의 최종 결과는 서버 응답을 따른다.

### 4.4 동시 입력과 공정성

- 서버는 각 목표에 대해 최초의 원자적 획득만 허용한다.
- 판정 기록에는 목표 ID, 플레이어 ID, 서버 수신 시각, 검증 결과, 경기 시퀀스 번호를 남긴다.
- 단순한 클라이언트 시각만 믿지 않으며 클라이언트가 점수나 성공 여부를 결정하지 않는다.
- 초기 버전은 이해하기 쉬운 **서버 도착 선착순**을 사용한다.
- 지역 간 지연이 경쟁성을 크게 훼손할 경우, 추후 제한적인 지연 보정 또는 지역별 매칭을 검토한다. 보정 규칙은 사용자에게 설명 가능하고 악용하기 어려워야 한다.
- 접속 지연이 큰 사용자는 경기 전후에 네트워크 상태 안내를 받는다.

### 4.5 점수 예시

| 요소 | 예시 |
|---|---:|
| 기본 단어 획득 | 100점 |
| 긴 단어/짧은 문장 | 120~250점 |
| 콤보 배율 | 최대 ×2.0 |
| 위험 목표 보너스 | +20~100점 |
| 쟁탈 승리 연출 | 점수 외 `STEAL!` 표시 |
| 오타 | 콤보 종료, 필요 시 소폭 감점 |

수치는 프로토타입 플레이테스트로 조정한다. 긴 문자열은 입력 시간이 더 들기 때문에 점수 효율이 짧은 단어보다 지나치게 낮지 않게 설계한다.

## 5. 콤보와 자동 방해

### 5.1 기본 원칙

- 목표를 연속으로 정확히 획득하면 콤보가 1씩 증가한다.
- 오타, 모드별 피격, 또는 일정 시간 동안의 미획득으로 콤보가 종료된다.
- 쟁탈 패배는 정확한 입력이었다는 점을 고려해 기본적으로 콤보를 직접 끊지 않고 짧은 유예를 적용하는 안을 우선 테스트한다.
- 방해 아이템을 직접 골라 사용하는 조작보다, 콤보 임계치에서 자동 발동하는 구조를 기본으로 한다.
- 방해는 **짧고 읽을 수 있으며 대응 가능**해야 한다. 타이핑을 강제로 대신하거나 키 입력을 바꾸지 않는다.

### 5.2 콤보 단계 예시

| 콤보 | 효과 | 지속/제한 |
|---:|---|---|
| 3 | 점수·사운드 강화, 개인 피드백 | 즉시 |
| 5 | 상대 1명 또는 선두에게 약한 화면 흔들림 | 약 0.5초 |
| 8 | 목표 일부에 짧은 블러 | 약 0.8초 |
| 12 | 화면 한 구역에 먹물 얼룩 | 약 1.2초 |
| 16+ | 강화 연출 + 블러/먹물 중 하나 | 최대 1.5초, 연속 발동 쿨다운 적용 |

### 5.3 대상 선정

- 1대1: 상대 플레이어에게 적용한다.
- 개인전: 기본적으로 현재 선두 또는 자신보다 한 단계 위 순위의 플레이어를 대상으로 한다.
- 팀전: 상대 팀 전체에 약한 효과 또는 상대 팀 선두에게 강한 효과 중 모드별로 선택한다.
- 협동전: 상대 방해 대신 팀 버프, 보스 약화, 위험 패턴 상쇄로 변환한다.

### 5.4 불쾌감 방지 장치

- 동일 대상에게 연속 방해가 중첩되지 않도록 보호 시간과 최대 강도를 둔다.
- 방해 중에도 현재 입력창과 입력한 글자는 읽을 수 있어야 한다.
- 광과민성, 멀미를 고려해 화면 흔들림·섬광·블러 강도 조절 및 감소 옵션을 제공한다.
- 랭크에서는 무작위성이 강한 방해를 줄이고 예측 가능한 임계치와 패턴을 사용한다.
- 초보 플레이리스트에서는 방해를 약화하거나 비활성화할 수 있다.

## 6. 실시간 멀티플레이 구조

### 6.1 경기 형식

- 빠른 대전: 비슷한 실력과 지역을 우선해 자동 매칭한다.
- 랭크 대전: 시즌 점수와 모드 숙련도를 반영한다.
- 친구 방: 방 코드, 규칙 설정, 관전, 재대전을 지원한다.
- 연습/봇: 네트워크 경쟁 없이 기본 입력과 모드를 익힌다.

### 6.2 서버 권위 모델

서버가 다음 상태의 최종 권한을 갖는다.

- 목표 생성과 활성/획득/만료 상태
- 제출 순서와 문자열 유효성
- 점수, 콤보, 방해 발동, 승패
- 경기 시간과 난수 시드

클라이언트는 입력, 예측 강조, 애니메이션, 사운드 표현을 담당한다. 서버 이벤트에는 증가하는 시퀀스 번호를 붙여 재전송이나 순서 역전을 안전하게 처리한다.

### 6.3 연결 예외 처리

- 짧은 끊김: 제한 시간 내 재접속과 상태 스냅샷 복구.
- 장기 이탈: 모드에 따라 패배 처리, 봇 대체 또는 팀 페널티 완화.
- 중복 제출: 요청 ID 기준으로 한 번만 처리한다.
- 늦은 응답: 이미 종료된 목표 또는 경기의 제출은 무효 처리한다.
- 서버 장애: 성립되지 않은 랭크 경기는 점수에 반영하지 않는다.

### 6.4 부정행위 대응

- 비현실적인 입력 간격, 반복 패턴, 완벽한 반응 시간, 자동화 의심 행동을 기록한다.
- 클라이언트가 보낸 WPM이나 점수를 신뢰하지 않고 서버 이벤트로 재계산한다.
- 비정상 입력은 즉시 영구 제재하기보다 탐지 점수, 리플레이/로그 검토, 단계별 제재를 사용한다.
- 공개 랭킹에는 검증되지 않은 경기 기록을 지연 반영할 수 있다.

## 7. 공통 시스템

### 7.1 타이핑 지표

- WPM 또는 한국어에 적합한 분당 타수(CPM)
- 정확도
- 총 획득 수와 쟁탈 승률
- 최대 콤보
- 평균 반응 시간
- 모드별 기여도: 명중률, 방어량, 보스 피해량 등

한국어와 영어의 입력 단위가 다르므로 언어 간 WPM을 그대로 동일 선상에서 랭크 점수로 비교하지 않는다.

### 7.2 단어 콘텐츠 시스템

- 언어, 난도, 길이, 품사, 테마, 금칙어 태그를 가진 단어 데이터베이스를 사용한다.
- 초보는 짧고 구분이 쉬운 단어 위주, 상위 난도는 유사 접두사와 짧은 문장을 섞는다.
- 모욕적 표현, 개인정보처럼 보이는 문자열, 입력하기 부적절한 단어는 필터링한다.
- 계절 이벤트나 테마 오락기에 맞는 단어 팩을 운영할 수 있다.
- 사용자 제작 단어 팩은 신고, 사전 검수, 비공개 방 제한을 거쳐 단계적으로 도입한다.

### 7.3 난도와 접근성

- 글자 크기, 고대비, 색약 팔레트, 배경 움직임 감소, 화면 흔들림 감소를 제공한다.
- 키 재지정, 전송 방식, 사운드별 볼륨을 조절할 수 있다.
- 초보 모드는 목표 수, 문자열 길이, 방해 강도를 낮춘다.
- 읽기 어려움이 있는 플레이어를 위해 가독성 우선 비픽셀 폰트 옵션을 제공한다.
- 채팅은 프리셋 이모트 중심으로 시작해 운영 위험을 낮춘다.

### 7.4 튜토리얼

1. 한 개 목표 입력 및 전송
2. 여러 목표 중 선택
3. 다른 플레이어와 같은 목표 쟁탈
4. 콤보와 자동 방해 체험
5. 결과 지표와 다음 오락기 안내

전체 튜토리얼은 3분 이내, 건너뛰기와 재실행을 지원한다.

### 7.5 소셜

- 친구 초대, 파티, 방 코드, 최근 함께한 플레이어
- 감정표현과 결과 화면 스탬프
- 신고, 차단, 닉네임 필터
- 관전 및 리플레이는 MVP 이후 검토

## 8. 미니게임 구성

공통 입력 엔진은 공유하지만, 아래 모드들은 승리 조건과 주요 판단을 다르게 설계한다.

### 8.1 단어 쟁탈전 — Word Grab

- **유형:** 개인 경쟁 / 2~8명
- **핵심:** 화면의 3~5개 목표를 먼저 정확히 전송해 점수를 획득한다.
- **차별점:** 어떤 목표를 노릴지와 상대가 노리는 목표를 읽는 심리전.
- **승리:** 제한 시간 종료 시 최고 점수.
- **특수 요소:** 긴 문장 고득점, 황금 단어, 연속 스틸 보너스.
- **역할:** 게임 전체의 표준 규칙이자 MVP 핵심 모드.

### 8.2 접시 사격 — Type & Shoot

- **유형:** 개인 경쟁 / 2~6명
- **핵심:** 화면을 가로지르는 접시의 단어를 입력하면 총알이 발사되어 해당 접시를 명중시킨다.
- **차별점:** 이동 속도, 궤적, 남은 노출 시간을 고려한 목표 우선순위.
- **승리:** 제한 시간 내 명중 점수 합계.
- **특수 요소:** 작은 접시, 곡선 비행, 콤보 멀티샷, 놓친 접시 페널티.
- **연출:** 입력 완료와 동시에 총성, 반동, 픽셀 파편, HIT 숫자 표시.

### 8.3 좀비 타이핑 디펜스 — Last Keyboard

- **유형:** 협동 / 1~4명
- **핵심:** 기지로 다가오는 좀비 위의 단어를 입력해 처치한다.
- **차별점:** 가까운 적, 강한 적, 특수 적 중 무엇을 먼저 막을지 역할 분담.
- **승리:** 정해진 웨이브 생존.
- **특수 요소:** 방어선 체력, 갑옷을 가진 장문 좀비, 동시 처치 폭발 좀비.
- **콤보 변환:** 상대 방해 대신 광역 공격 또는 기지 수리 게이지 충전.

### 8.4 보스 레이드 — Keyboard Raid

- **유형:** 협동 / 2~6명
- **핵심:** 보스의 부위와 패턴에 붙은 문자열을 입력해 피해를 주고 공격을 저지한다.
- **차별점:** 공격, 방어, 해제 목표가 동시에 등장하며 팀이 우선순위를 합의해야 한다.
- **승리:** 제한 시간 내 보스 처치.
- **특수 요소:** 부위 파괴, 브레이크 게이지, 전멸기 문장, 팀 콤보.
- **지표:** 피해량만이 아니라 패턴 차단과 팀 구조 기여도를 함께 표시한다.

### 8.5 니트로 레이싱 — Type Racer Arcade

- **유형:** 개인 경쟁 / 2~8명
- **핵심:** 목표를 정확히 입력해 가속하고, 긴 목표로 니트로를 충전한다.
- **차별점:** 짧고 안전한 가속과 길고 위험한 니트로 사이의 선택.
- **승리:** 먼저 결승선을 통과하거나 시간 종료 시 가장 앞선 플레이어.
- **특수 요소:** 코너에서는 정확도, 직선에서는 속도에 보너스. 오타 시 순간 감속.
- **방해 표현:** 먹물 대신 도로 표지 흔들림, 타이어 연기 등 테마형 시야 방해.

### 8.6 보물 사냥 — Treasure Type

- **유형:** 경쟁 탐색 / 2~6명
- **핵심:** 여러 상자의 단어를 입력해 열고 열쇠, 점수, 함정을 발견한다.
- **차별점:** 정보가 불완전한 위험·보상 선택과 경로 경쟁.
- **승리:** 제한 시간 내 보물 가치 합계.
- **특수 요소:** 긴 문장 금고, 가짜 상자, 지도 조각 세트, 다른 플레이어가 먼저 연 상자의 흔적.
- **운영 원칙:** 랭크에서는 운보다 선택과 입력 실력의 비중이 높도록 보상 범위를 제한한다.

### 8.7 풍선 팝 — Balloon Burst

- **유형:** 파티 경쟁 / 2~8명
- **핵심:** 떠오르는 풍선의 단어를 입력해 화면 밖으로 나가기 전에 터뜨린다.
- **차별점:** 목표가 많아지는 군집 처리와 짧은 반응 시간.
- **승리:** 획득 점수 또는 지정 색 풍선 세트 완성.
- **특수 요소:** 연쇄 폭발, 감점 폭탄, 색상 미션, 거대 문장 풍선.
- **접근성:** 색상 외 모양과 아이콘을 함께 사용한다.

### 8.8 심해 낚시 — Deep Type Fishing

- **유형:** 경쟁·캐주얼 / 2~6명
- **핵심:** 물고기 단어를 먼저 입력해 입질을 잡고, 이어지는 짧은 문장으로 끌어올린다.
- **차별점:** 1차 선착순과 2차 정확도 유지의 두 단계 입력.
- **승리:** 잡은 물고기의 총 가치.
- **특수 요소:** 희귀 어종, 도망 게이지, 보물 상자, 너무 욕심내면 줄이 끊어지는 장문 목표.
- **템포:** 다른 모드보다 완급이 있으며 수집형 만족을 강조한다.

### 8.9 왕관 쟁탈전 — Crown Keeper

- **유형:** 개인 경쟁 / 3~8명
- **핵심:** 중앙의 왕관 단어를 획득하면 왕이 되고, 왕 전용 목표를 처리해 보유 시간을 늘린다.
- **차별점:** 점수 획득보다 왕관을 빼앗고 지키는 상태 전환과 집중 견제.
- **승리:** 누적 왕관 보유 시간이 가장 긴 플레이어.
- **특수 요소:** 왕은 고득점 기회를 얻지만 더 어려운 문자열과 공개 표적 페널티를 받는다.
- **역전 장치:** 하위 플레이어도 왕관 목표 쟁탈에는 동일하게 참여한다.

### 8.10 키보드 서바이벌 — Last Typist

- **유형:** 탈락 경쟁 / 4~12명
- **핵심:** 짧은 라운드마다 제한된 목표를 쟁탈하고 최하위권이 탈락한다.
- **차별점:** 라운드가 갈수록 목표 수가 줄고 문자열 난도가 높아지는 생존 압박.
- **승리:** 마지막까지 생존한 플레이어.
- **특수 요소:** 안전선, 동점자 타이브레이커 문장, 관전자 응원 이펙트.
- **공정성:** 한 번의 네트워크 지연으로 즉시 탈락하지 않도록 초반 라운드는 누적 점수 또는 보호권을 사용한다.

### 8.11 모드 차별화 요약

| 모드 | 핵심 실력 | 주요 목표 | 감정 |
|---|---|---|---|
| 단어 쟁탈전 | 선착순·목표 선택 | 점수 최대화 | 직접 경쟁 |
| 접시 사격 | 반응·이동 예측 | 명중 | 파괴 쾌감 |
| 좀비 디펜스 | 우선순위·협력 | 생존 | 압박과 구조 |

| 니트로 레이싱 | 위험·보상 | 선두 도착 | 추월 |
| 보물 사냥 | 탐색·선택 | 가치 수집 | 발견 |

## 9. 오락기 선택형 로비

### 9.1 공간 콘셉트

플레이어는 1990년대~2000년대 초반의 네온 오락실을 현대적으로 재해석한 로비에 입장한다. 각 미니게임은 고유한 캐비닛 외형, 간판, 데모 화면, 대표 사운드를 가진 오락기로 표현된다.

### 9.2 주요 동선

- 중앙: 빠른 대전 및 추천 오락기
- 좌측 구역: 경쟁형 게임기
- 우측 구역: 협동·파티형 게임기
- 후면: 랭크, 시즌, 리더보드 전광판
- 카운터: 스킨, 프로필, 설정, 튜토리얼

### 9.3 조작 방식

- 키보드 방향키/WASD 또는 마우스로 게임기를 선택한다.
- 게임기 앞에서 인원, 예상 대기 시간, 한 판 길이, 난도, 핵심 규칙을 즉시 확인한다.
- 공간 이동이 번거로운 사용자를 위해 목록형 “게임 선택” 메뉴도 항상 제공한다.
- 파티장은 함께 게임기 앞으로 이동하거나 파티 리더의 선택에 동의한다.

### 9.4 로비의 기능적 목적

- 여러 미니게임이 하나의 세계에 속한다는 인상을 준다.
- 시즌 이벤트와 신규 오락기 추가를 공간 변화로 보여준다.
- 인기 모드 쏠림을 전광판 보너스와 오늘의 추천으로 완화한다.
- 대기 시간을 플레이어 구경, 연습 타이핑, 스킨 표현의 시간으로 바꾼다.

## 10. 아트 방향

### 10.1 비주얼 콘셉트

- 1990년대~2000년대 초반 오락실풍 **2D 픽셀 아트**.
- 저해상도 감성을 유지하되 현대 화면에서 읽기 좋은 HD 픽셀 표현.
- 어두운 남색·보라색 실내에 네온 시안, 마젠타, 노랑을 포인트로 사용.
- CRT 스캔라인, 색수차, 글로우는 선택 옵션으로 제공하고 가독성을 해치지 않게 제한.
- 게임별 배경은 달라도 공통 UI 프레임, 타이포그래피, 이펙트 규칙으로 통일한다.

### 10.2 픽셀 제작 기준 초안

- 논리 해상도와 픽셀 배율을 프로젝트 초기에 고정한다.
- 스프라이트는 제한 팔레트와 명확한 실루엣을 우선한다.
- 목표 문자열은 픽셀 폰트만 고집하지 않고 가독성 우선 폰트를 사용한다.
- 성공, 실패, 쟁탈 패배, 방해 피격은 색상뿐 아니라 형태와 모션으로 구분한다.
- 에셋 구매·외주·AI 보조 사용 시 라이선스, 상업 이용, 데이터 출처, 스타일 일관성을 확인한다.

### 10.3 대표 연출

- 단어 획득: 글자가 목표물 안으로 빨려 들어가며 파열.
- 스틸 승리: 목표 위에 `CATCH!` 또는 `STEAL!` 도장.
- 접시 명중: 총구 섬광, 1~2프레임 히트 스톱, 픽셀 파편.
- 콤보 상승: UI 테두리 발광과 사운드 음정 상승.
- 먹물 방해: 불투명 검정 덩어리보다 가장자리 픽셀이 번지는 짧은 얼룩.

## 11. UI/UX

### 11.1 플레이 화면 정보 우선순위

1. 입력해야 할 목표 문자열
2. 현재 입력값과 일치/오타 상태
3. 목표의 남은 시간 또는 위험도
4. 점수, 순위, 콤보
5. 방해 예고 및 상태
6. 네트워크 품질과 시스템 안내

### 11.2 기본 화면 구성

- 중앙 플레이필드: 3~5개 목표와 모드 오브젝트.
- 하단 중앙: 큰 입력창, 조합 중 글자, 전송 안내.
- 상단: 남은 시간, 점수, 순위.
- 좌우: 플레이어 상태, 콤보, 방해 예고.
- 모서리: 연결 상태, 설정, 접근성 빠른 메뉴.

### 11.3 입력 피드백

- 일치한 글자: 즉시 밝게 강조.
- 후보 목표: 테두리 또는 연결선으로 강조.
- 오타: 입력창의 짧은 진동과 낮은 오류음. 화면 전체 섬광은 피한다.
- 쟁탈 패배: “오타”와 구분되는 회색/보라색 피드백과 선취 플레이어 표시.
- 성공: 대상이 사라지는 순간과 서버 확정 시점을 최대한 가깝게 맞춘다.

### 11.4 결과 화면

- 승패와 순위를 먼저 보여준다.
- 개인 최고 기록, 정확도, 최대 콤보, 쟁탈 승률을 요약한다.
- “조금만 더 빨랐던 목표” 같은 개선 단서를 긍정적으로 제공한다.
- 재대전, 다음 추천 게임, 로비 버튼을 한 화면에 배치한다.

## 12. 사운드와 타격감

### 12.1 사운드 방향

- 칩튠, FM 신시사이저, 초기 디지털 샘플러 질감을 현대적으로 믹스한다.
- 모드마다 대표 테마는 다르지만 공통 성공음과 콤보 모티프를 공유한다.
- 키 입력음은 짧고 피로도가 낮게 하며 여러 세트를 선택할 수 있게 한다.
- 콤보가 오를수록 음정, 레이어, 리듬이 단계적으로 강화된다.

### 12.2 성공 순간의 피드백 묶음

한 번의 유효 입력에 다음 요소를 50~150ms 안에 묶어 제공한다.

- 선명한 성공음
- 목표 오브젝트의 1~2프레임 히트 스톱
- 작은 화면/오브젝트 흔들림
- 픽셀 파편 또는 잔상
- 점수와 콤보 팝업
- 필요 시 컨트롤러 진동

### 12.3 믹싱 원칙

- 자기 입력 성공음은 상대 성공음보다 분명하게 들린다.
- 오류음은 정보 전달은 하되 연속 오타 시 공격적으로 누적되지 않는다.
- 먹물·블러 등 방해는 발동 예고음을 먼저 줘 대응 가능성을 높인다.
- 음악, 키 입력, 효과, 음성/알림 볼륨을 별도로 조절한다.

## 13. 랭크, 시즌, 스킨

### 13.1 랭크

- 계정 전체의 기본 타이핑 실력 지표와 모드별 랭크를 분리한다.
- 매칭은 속도만이 아니라 정확도, 승률, 표본 수, 지역 지연을 함께 본다.
- 배치전 이후 브론즈~마스터 등 이해하기 쉬운 티어를 제공한다.
- 인구가 적은 모드는 캐주얼 중심으로 운영하고 충분한 표본이 생긴 뒤 랭크를 연다.
- 시즌 종료 시 과도한 초기화를 피하고 소프트 리셋을 사용한다.

### 13.2 시즌

- 8~12주 단위 시즌을 기본안으로 검토한다.
- 시즌마다 오락실 장식, 테마 단어 팩, 한정 도전, 신규 오락기 또는 변형 규칙을 제공한다.
- 일일 과제보다 주간·시즌 과제를 중심으로 강박적인 접속을 줄인다.
- 경쟁 보상은 실력 과시용 장식으로 제한하고 성능 우위를 주지 않는다.

### 13.3 스킨과 수익화 원칙

- 아바타, 키보드, 타건 이펙트, 총기/차량/낚싯대 외형, 게임기 프레임, 프로필 카드.
- 목표 글자의 가독성이나 피격 판정에 영향을 주는 스킨은 금지한다.
- 유료 상품은 꾸미기 중심이며 점수, 방해 강도, 입력 판정 이점을 판매하지 않는다.
- 랜덤형 상품 도입 여부는 대상 연령, 지역 규제, 서비스 신뢰를 고려해 신중히 결정한다.

## 14. MVP 범위

### 14.1 MVP 목표

“여러 사람이 같은 목표를 보고 먼저 정확히 전송해 획득하는 경험이 지연 상황에서도 재미있고 공정하게 느껴지는가?”를 검증한다.

### 14.2 포함 범위

- PC 웹 또는 단일 PC 플랫폼
- 한국어 우선, 필요 시 영어 소규모 단어 팩
- 게스트 또는 간단 계정
- 2~4인 실시간 방 생성·참가
- **단어 쟁탈전 1개 모드**
- 화면 동시 목표 3~5개
- 서버 권위 선착순 판정
- 점수, 정확도, 콤보, 최대 콤보
- 자동 방해 2종: 짧은 블러, 먹물 얼룩
- 30초 및 60초 라운드
- 최소한의 로비/방 코드/결과 화면
- 기본 픽셀 아트 테마와 성공·실패 사운드
- 재접속·중복 제출의 기본 처리
- 서버 로그와 핵심 플레이 분석 이벤트

### 14.3 제외 범위

- 10개 미니게임 전체
- 완전한 공간형 오락실 로비
- 랭크 시즌, 배틀 패스, 상점
- 관전, 리플레이, 토너먼트
- 사용자 제작 단어 팩
- 모바일·콘솔 크로스플레이
- 길드와 복잡한 소셜 시스템

### 14.4 MVP 성공 기준 초안

- 첫 플레이어가 설명 후 3분 이내 정상적인 한 판을 완료한다.
- 내부 목표 환경에서 제출 성공의 서버 처리 오류가 0.1% 미만이다.
- 동일 목표 경쟁 결과가 모든 클라이언트에서 일치한다.
- 목표 지역의 일반적인 네트워크 환경에서 성공 피드백이 답답하지 않다.
- 플레이테스트 참가자의 다수가 재대전을 자발적으로 선택한다.
- 블러/먹물 방해가 “재미있는 압박”인지 “입력을 막는 불쾌감”인지 정성·정량 평가한다.

## 15. 기술 구조 초안

### 15.1 원칙

- 서버 권위(authoritative server)
- 입력과 연출의 낮은 지연
- 모드별 로직을 교체 가능한 구조
- 단어 콘텐츠와 게임 규칙의 데이터화
- 판정 재현이 가능한 이벤트 로그

### 15.2 구성 요소

| 계층 | 책임 |
|---|---|
| 게임 클라이언트 | 렌더링, 로컬 입력, IME 처리, 후보 강조, 예측 연출, 사운드 |
| 실시간 게이트웨이 | WebSocket 연결, 인증, 방 입장, 메시지 전달, 재연결 |
| 매치 서버 | 목표 생성, 제출 검증, 원자적 획득, 점수/콤보/방해, 경기 시간 |
| 매치메이킹 | 지역, 실력, 파티 조건에 따른 방 구성 |
| 계정/진행 서버 | 프로필, 설정, 스킨, 랭크, 시즌 진행도 |
| 콘텐츠 서비스 | 단어 팩, 금칙어, 모드 설정, 밸런스 값 버전 관리 |
| 데이터/운영 | 로그, 분석, 신고, 부정행위 탐지, 대시보드 |

### 15.3 실시간 메시지 예시

- `match_snapshot`: 활성 목표, 점수, 콤보, 남은 시간 전체 상태
- `target_spawned`: 목표 ID, 문자열, 위치/오브젝트, 만료 시각
- `submission_attempt`: 요청 ID, 목표 후보, 입력 문자열, 클라이언트 시각
- `submission_result`: 성공/쟁탈 패배/오타/만료, 획득자, 서버 시퀀스
- `interference_triggered`: 발동자, 대상, 효과, 시작/종료 시각
- `match_finished`: 순위, 지표, 보상, 랭크 변화

### 15.4 판정 흐름

1. 클라이언트가 입력 문자열과 요청 ID를 전송한다.
2. 서버가 경기·플레이어·목표 상태를 확인한다.
3. 정규화 규칙을 적용하고 정확히 일치하는 활성 목표를 찾는다.
4. 목표 획득을 원자적으로 시도한다.
5. 최초 성공자에게 점수와 콤보를 적용한다.
6. 콤보 임계치라면 방해 이벤트를 생성한다.
7. 모든 클라이언트에 하나의 순서화된 결과를 방송한다.
8. 획득된 목표를 제거하고 새 목표를 생성한다.

### 15.5 후보 기술

- 클라이언트: 웹 기반 Canvas/WebGL 엔진 또는 범용 2D 게임 엔진
- 실시간 통신: WebSocket 기반 양방향 메시징
- 서버: 단일 지역의 상태 보유형 매치 프로세스로 시작
- 저장소: 계정·진행도용 관계형 DB, 세션/매칭용 인메모리 저장소
- 배포: 초기에는 한 지역, 부하와 지연 데이터에 따라 다지역 확장

특정 엔진과 언어는 팀 역량, 배포 플랫폼, 한글 IME 품질, 네트워크 라이브러리 성숙도를 비교한 뒤 기술 프로토타입에서 결정한다.

### 15.6 테스트 항목

- 같은 목표에 여러 제출이 동시에 도착하는 경쟁 조건
- 중복·지연·순서 역전 메시지
- 50/100/200ms 지연 및 패킷 손실 환경
- 한글 조합, 백스페이스, 붙여넣기, 특수문자 입력
- 목표 교체 직전 제출과 경기 종료 직전 제출
- 재접속 후 스냅샷 일관성
- 자동 입력 의심 패턴과 속도 한계

## 17. 향후 업데이트 로드맵

### 단계 A — 코어 검증

- 단어 쟁탈전 프로토타입
- 로컬 및 온라인 2~4인 테스트
- 서버 선착순 판정과 네트워크 체감 검증
- 콤보, 블러, 먹물 밸런스 실험

### 단계 B — MVP/비공개 테스트

- 방 코드, 간단 프로필, 결과 지표
- 초보 튜토리얼과 접근성 옵션
- 기본 픽셀 아트 및 사운드 패스
- 운영 로그, 오류 수집, 부정행위 기초 탐지

### 단계 C — 미니게임 확장

- 접시 사격과 좀비 디펜스 우선 추가
- 공통 모드 프레임워크 안정화
- 공간형 오락실 로비
- 친구, 파티, 캐주얼 매칭

### 단계 D — 경쟁·라이브 서비스

- 랭크, 시즌, 리더보드
- 스킨과 꾸미기 경제
- 니트로 레이싱, 왕관전, 서바이벌
- 관전, 리플레이, 커뮤니티 대회 도구

### 단계 E — 장기 확장

- 보스 레이드, 보물 사냥, 풍선 팝, 심해 낚시
- 다국어 단어 팩과 지역 서버
- 사용자 제작 콘텐츠의 제한적 도입
- 모바일·콘솔 입력 경험 연구
- 교육기관 또는 타자 학습용 별도 플레이리스트 검토

## 20. 결론

Catch Typing의 가장 중요한 검증 대상은 “타자가 빠른 사람이 이기는가”보다 **“여러 목표 중 하나를 골라 먼저 정확히 가져가는 순간이 반복해서 재미있는가”**이다. 따라서 첫 프로토타입은 단어 쟁탈전, 서버 판정, 콤보 자동 방해, 즉각적인 타격감에 집중해야 한다.

이 코어가 성립하면 접시 사격처럼 움직임을 더하고, 좀비 디펜스처럼 협력을 더하고, 레이싱처럼 자원 선택을 더하는 방식으로 미니게임을 확장할 수 있다. 오락실형 로비와 픽셀 아트는 이 다양한 규칙을 하나의 서비스로 묶는 세계관이자, 신규 콘텐츠를 자연스럽게 소개하는 장치가 된다.
